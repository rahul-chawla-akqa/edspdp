Post data flow

Post pages merge AEM-authored placeholders with JSONPlaceholder on Adobe CDN. A cache hit never invokes the edge function.

When the API-filled post is generated

The posts-composer edge function runs on a CDN cache miss for GET/HEAD /posts/post-N on the mapped custom domain. It does not run on *.aem.live / *.aem.page, in Universal Editor, or when the stitched document is already in CDN cache.

1. Author / publish (placeholders only)

Author in Universal Editor

Placeholder page and post-body block. Overlay is not registered for /posts/*.

→

AEM Author HTML

Authored shell plus empty or numeric post-body. Not the API JSON.

→

Content bus

Stores authored HTML only. EDS stores no JSONPlaceholder fields.

→

EDS origin

.aem.page / .aem.live serve the placeholder page.

Preview or publish never calls JSONPlaceholder. A visitor on the custom domain is what triggers stitching.

2. Visitor request, cache hit (no stitch, no JSONPlaceholder on the critical path)

Shopper GET /posts/post-N

Browser requests the custom hostname mapped in Cloud Manager.

→

Adobe CDN cache

skipCache is false. A cached document never invokes Fastly Compute.

→

Stitched HTML

Last miss’s document. post-body already has api-rendered.

→

Browser

Block JS skips hydrate. No JSONPlaceholder call.

Fallback: *.aem.live, Universal Editor, and local drafts never hit this function; post-data.js hydrates in the browser.

3. Visitor request, cache miss (HTML stitched on the edge)

Shopper GET

Custom domain, path matches /posts/post-N, no sentinel header.

→

Adobe CDN miss

cdn.yaml selects origin edgefunction-posts-composer.

→

Edge function

Fastly Compute posts-composer. Parses id from the path or authored block text.

→

Loopback EDS HTML

GET same path with x-edgefunction-request: true so the function cannot recurse.

→

JSONPlaceholder

GET /posts/{id}. JSON is not stored in AEM; used only to fill the block.

→

Stitched HTML cached

Replace .post-body, add api-rendered. Browser TTL 60s; CDN TTL 3600s; keys posts post-N.

If EDS is not 200, that status is forwarded. If the API fails or the placeholder is missing, authored HTML is returned so client hydrate can still fill the block. Unexpected exceptions return 502.

4. Refresh after HTML or API changes (stitched cache is stale until purge)

A. Outer CDN purge

AEM CDN Cache Purge API with surrogate keys posts and post-N. Clears the HTML the browser receives.

→

B. Inner fetch-cache purge

aio aem edge-functions purge-cache posts-composer --surrogateKey post-N. Clears EDS HTML and JSONPlaceholder responses tagged by the function.

→

C. Next miss restitches

Purge both layers. Purging only the CDN lets the next miss restitch from a stale fetch cache.

Author republish of the placeholder page, or a change in API data, does not rewrite live HTML by itself.

5. Where data is stored

What Stored? Where When written
Authored post shell Yes AEM Author Author save
Merged HTML (post-body, api-rendered) Yes — CDN snapshot Adobe CDN (custom domain) Successful stitch on cache miss; TTL 3600s
EDS HTML and API JSON in fetch cache Yes — inner TTL 300s Fastly fetch cache Function fetch with CacheOverride
Post JSON from JSONPlaceholder No durable store in AEM Function memory, fetch cache, or a browser Map on hydrate Cache miss stitch, or client hydrate if the function did not fill the block
Price-style live fields Not in this PoC — JSONPlaceholder posts are treated as stitchable snapshot data
